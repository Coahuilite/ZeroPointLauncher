# 平台无关核心与适配边界

本文是 v0.1 的架构提案；已确认方向和产品范围见[入口](README.md)。模块名表达职责，不提前固定最终包名、JPMS 划分或每个端口的 Java 签名。

## 核心服务实例管理，适配器负责接入环境

```text
Qz 桌面 / CLI / 测试驱动
             │ 调用
             ▼
          应用用例
    ┌────────┼────────┐
  layerfs  minecraft  content
    └────────┼────────┘
        定义所需端口
             ▲ 实现
    宿主适配器 / 外部服务适配器

composition root 装配具体实现；核心不引用适配器。
```

应用用例负责安装、派生、升级、准备、启动和导出。三个领域内核负责纯决策。核心可依赖 JDK 和经过选择的通用库，但不得依赖 Qz、JavaFX、GLFW、Windows API 或 Minecraft 游戏类加载环境。

## 职责与数据所有权

| 边界 | 拥有的规则与状态 | 不负责 |
| --- | --- | --- |
| application | 实例用例、操作状态、协调、实例持久化端口、认证使用流程 | 控件状态、平台系统调用 |
| layerfs | 逻辑路径、层合并、来源解释、差异、物化计划 | 模组版本选择、游戏参数、账户认证 |
| minecraft | 游戏组件解析、Java 约束、平台规则求值、启动计划 | 文件继承优先级、宿主进程 API |
| content | 制品身份、模组/包元数据、导入归一化、导出内容选择 | 直接覆盖运行目录、持有 UI 对象 |
| ui-qz | 页面、输入、展示投影、UI 调度 | 下载编排、创建链接、运行时选择规则 |
| host adapters | 文件能力、磁盘执行、Java 探测、进程、秘密存储 | 自行改变文件写入语义或游戏兼容规则 |
| service adapters | 网络传输、元数据源、远程认证、格式解码 | 决定实例继承和覆盖结果 |

概念归所属模块，不新建包揽所有模型的 `Common/Core`。跨边界使用小型不可变值和端口；接口按替换需求设置，不要求每个类都有接口。首版通过构造注入装配，不先引入动态插件协议或进程间 RPC。

### 当前文件工作区的落地边界

`layerfs` 保留纯解析，并增加 `WorkspaceModel` 和 `WorkspacePlanner`：接收基线与当前逻辑快照，决定首次复制、同基线保留或拒绝基线变更，分类私有 delta。模型不携带磁盘 `Path`，不读取系统属性或文件。

`workspace-nio` 单向依赖 `layerfs`。`NioWorkspace` 负责复制、扫描、侧置状态和操作占用，把实际字节转换为核心可比较的内容身份；`ArtifactSource` 为该宿主提供不可变制品的字节流。目标名称限制留在宿主 `NamePolicy`。CLI 示例装配这些对象，旧的纯解析入口继续可用。

当前 NIO 入口接收调用者明确指定的磁盘位置，是文件工作区适配器，不是完整的实例应用服务。之后应用层协调游戏组件、会话占用与启动时，复用这些核心规则；不将 NIO 路径传进游戏规则或 Qz 页面模型。

## 实例修订同时固定配置与内容

基础整合包、玩家分享的预设和自己维护的派生实例属于同一种实体，拥有稳定身份、修订、父引用和内容规则。汉化、性能配置、服务器客户端配置等是用途，而不是不同的继承级别或专用子类。共享预设可以作为实例使用，也可以继续派生；分享的是选定实例修订，不是另一种“低一级配置层”。

层是实例修订内部的内容表达，不能替代实例身份。`sharedLayers` 表达显式不可变内容复用，不用来降格表示玩家共享预设。单父继承仍是当前基线，本次澄清不引入多父继承或任意多预设合并协议。

运行目录里的个人改动属于工作区 delta。用户在自己维护的实例修订中声明的配置和规则可以被继承；游戏运行后产生、尚未提升的新增/修改/删除不自动成为修订的一部分。这两类“个人修改”必须在 API 和界面上区分。

派生实例默认沿用固定父修订的有效游戏配置，不要求用户重新选择 Minecraft、加载器和整合包组件。实例配置继承与文件层继承属于同一实例修订，但使用各自的解析规则：

- 游戏组件描述作为一组，包含明确的游戏版本、加载器及包所需附加组件；可移植启动偏好作为另一组，包含用户参数和 Java 选择偏好等。
- 子修订未声明某组时继承父修订的有效值；显式声明时整组替换，不使用任意 JSON 深合并。组内参数列表同样是完整列表，不把父子字符串参数盲目拼接。
- 仅添加本地模组可以只改变文件层，继续继承组件与偏好。首次创建无父实例时，必须显式给出游戏组件组，启动偏好可采用产品默认值。
- 账户绑定、凭据、机器上的实际 Java 路径和宿主目录不随内容继承；执行时由当前实例/设备绑定。可移植 Java 偏好仍须接受运行时约束校验。
- 切换父修订时，组件、偏好和文件基线共同进入升级预览；保留的子级整组覆盖须显示其阻止继承哪些上游变化，并重新计算 Java、加载器与目标环境约束。
- 配置和文件必须以同一目标实例修订准备和提交，不能出现新组件配置配旧文件基线却标记为就绪的状态。冲突未解决则保留原可用修订。

应用层负责实例级继承及修订协调，将有效配置交给 Minecraft 内核。Minecraft/加载器元数据自身的继承、补丁与参数规则仍由 Minecraft 内核解析；两种继承不能互相替代。对应验收见 RT-15。

## 平台作为事实输入

`HostCapabilities` 表达文件系统大小写规则、链接能力和可用凭据服务等事实；`TargetEnvironment` 表达游戏目标操作系统、架构及实际选中的游戏 JVM。两者不能以当前启动器进程的系统属性代替。

- 核心依据目标环境计算游戏 natives、库规则和参数；宿主只执行对应文件与进程操作。
- 文件系统核心使用规范化逻辑路径；盘符、本地路径编码、链接 API 和路径约束由宿主边界处理。
- 缺失宿主能力产生明确诊断或经选择的替代执行策略，不改变逻辑结果。
- Qz Platform 只承担 UI 宿主能力，不等于启动器的全部宿主适配。

## 关键端口及完成含义

| 端口概念 | 输入与输出 | 完成意味着什么 |
| --- | --- | --- |
| InstanceRepository | 稳定 ID、修订、预期当前版本 → 新修订或并发冲突 | 新版本持久可读，不覆盖其他操作的更新 |
| ArtifactSource / ArtifactStore | 制品标识、来源与完整性声明 → 受管理内容引用 | 获取及声明的完整性检查已完成，不是仅开始下载 |
| FileWorkspace | 物化计划、能力与预期状态 → 已就绪工作区或逐项错误 | 必要文件完成、提交记录可恢复，才可用于启动 |
| RuntimeCatalog | 探测请求 → 实际 Java 描述及探测失败 | 提供候选事实，不替应用决定兼容性 |
| CredentialStore / Authentication | 账户引用、认证请求 → 会话凭据或可处理失败 | 身份确认成功；秘密不混入普通实例和配置导出 |
| ProcessHost | 已解析启动请求 → 进程会话 | 创建成功可观察；后续退出通过独立结果报告 |

网络获取使用暂存和完成标记，下载未完成的文件不得进入可用制品集合。校验遵循来源协议；需要安全内容身份时使用相应完整性机制，不靠旧 CRC32 证明远程内容可信，也不要求每次展示实例都重算全部文件摘要。

## 应用操作与 UI 更新

操作返回 `OperationId`、状态快照、进度订阅、结果和取消入口。阶段名称与字节/项目计数是结构化字段，日志用于诊断，不作为业务成功信号。

```text
QUEUED → RUNNING → SUCCEEDED / FAILED / CANCELLED
```

提交中的取消请求必须被记录并得到结果，但只有安全取消完成才能进入 CANCELLED；已越过提交点的操作可以完成并报告取消未生效，不伪装为已回滚。不可中断区应短且有恢复记录。游戏创建后的生命周期以[运行时契约](runtime.md)为准，不能用取消准备任务代替终止游戏。

同一实例的准备、升级和启动交接串行化；应用拥有操作状态，宿主提供跨进程占用能力。相互独立的实例可并行，显式共享写资源另外协调。界面关闭时解除展示订阅，不因此终止应用任务或释放游戏会话占用；UI 线程不阻塞等待网络、磁盘和游戏进程。

工作线程只发布值和事件，由 UI 适配器投递到 Qz 的所属线程/状态域。进度可以合并刷新，最终结果和错误不能丢弃；游戏日志展示必须有界。

## 内容管理是通用能力

一个导入器把外部包转换为 `ImportPlan`：游戏组件、内容层、制品引用、来源信息和未解析条目。应用层批准并执行计划，导入器不直接写最终实例目录。

- GTNH 名称、版本和特殊启动组件放在包描述/适配器中。
- 自建实例可以从游戏组件开始，再添加本地 JAR；没有在线项目 ID 不妨碍管理文件。
- 模组身份、发布版本、实际文件与文件名分离；无法确定的依赖保留为未知，不伪造兼容结论。
- 更新依赖先产生变更计划，不静默替换整合包锁定制品或用户覆盖。
- 新下载源和新包格式复用现有实例、层和启动计划，不创建专用实例子类。
- 本地文件导入和联网制品获取分开，导出明确区分引用清单、可再分发内容及用户私有数据，不默认包含账户或存档。

`ImportPlan` 至少保留输入格式/版本、原始来源、确定的组件与制品、目标逻辑路径、声明的完整性、附带覆盖文件和未决事项。一个包的声明不能自动变成执行任意脚本的授权；首版不执行包内任意安装钩子。确需执行加载器安装器时，由明确支持的安装流程描述来源、参数及副作用范围。

导入先解码、归一化和校验，再获取内容，最后创建实例修订；重名显示名不等于覆盖现有身份。同一路径多制品、越界压缩条目、缺失必需文件等问题不能靠解压顺序解决。失败不得留下被标记为安装完成的实例。首个闭环只需支持经固定样本验证的 GTNH 输入与自建实例，不提前承诺所有包格式互通。

模组管理区分四个对象：来源项目、发布记录、实际制品、实例安装位置。解析到的游戏/加载器/依赖约束保留来源和适用范围；已知硬冲突阻止提交该方案，推荐项用于提示，未知内容允许保留但显示未验证。首版检查给定方案，不自动求解任意模组生态的完整依赖图，也不声称“没有发现冲突”就是运行兼容。包锁定制品的更新需要显式选择并形成新修订，用户覆盖继续按三方差异处理。

导出采用明确白名单：实例描述、来源与修订信息、所选覆盖，以及允许分发的内容。无法确认分发条件时保留可用引用或报告缺项；不能通过打包整个运行目录绕过选择。账户秘密始终排除，存档等用户数据只在用户另行选择的数据导出中包含。

## 持久化和发行边界

实例身份、修订、规则、来源和私有数据是持久事实；解析树、下载暂存、可重建运行制品是派生结果。用户数据不能因为目录叫作 runtime/cache 就被当作可丢弃缓存。

新格式应有 schema 版本、稳定 ID 和明确的旧格式导入入口。未知的新 schema 不得覆盖写回；一次迁移先预览，再写入新工作区，旧目录保持可恢复。具体文件布局和存储库实现随首个持久化切片确定。

启动器携带 Java 25 运行时；游戏 JVM 由运行时模型选择。发行按 OS/架构构建和验收，Qz 的 native 依赖只属于启动器进程。第一条真实桌面路线先用 Windows，核心的跨平台规则用目标环境夹具独立验证。

## 架构验收场景

| 编号 | 输入/动作 | 必须观察到的结果 |
| --- | --- | --- |
| AR-01 | 无显示设备、无网络的进程运行核心夹具 | 能解析实例、文件树和启动计划，不初始化 UI/native 设备 |
| AR-02 | 仅替换 Windows 宿主为另一个满足端口的实现 | 核心不改代码；相同逻辑输入结果相同，真实平台差异按能力报告 |
| AR-03 | 后台任务连续发布进度并失败 | UI 线程接收快照；失败可见；没有把日志文本当状态 |
| AR-04 | 同一实例同时请求准备与升级 | 一个操作等待或报告占用；不交错提交；不同独立实例可继续 |
| AR-05 | 导入 GTNH 样本与一个自建普通实例 | 二者使用同一实例和层模型；本地 JAR 可保留为未知元数据内容 |
| AR-06 | 获取制品中断、恢复或完整性不符 | 半成品不标记可用；错误关联制品；后续重试不被假成功缓存跳过 |
| AR-07 | 旧格式或未知新 schema 被读取 | 旧格式走显式导入；未知新格式拒绝覆盖，原数据仍可恢复 |
| AR-08 | 包含路径冲突、越界条目或获取失败的导入 | 产生具体错误，不执行包内任意脚本，不提交假完成实例 |
| AR-09 | 模组方案含已知硬冲突、推荐项和未知本地 JAR | 三类结果分别处理；不静默更换锁定制品，未知不伪造兼容 |
| AR-10 | 导出含个人覆盖、存档和账户信息的实例 | 仅包含所选可导出项；秘密始终排除，存档默认不包含 |
