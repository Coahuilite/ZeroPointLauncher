# 第三方发行身份：可派生，不冒充官方（提案）

状态：[公开讨论 Issue #1](https://github.com/Coahuilite/ZeroPointLauncher/issues/1)，2026-10-22；与 [MPL-2.0 候选](licensing.md)分别审议。以下是发行身份与品牌使用建议，不向软件许可证增添限制代码复制、修改或商业使用的条款。

## 让用户认清是谁发布的

本 fork 的维护与发布渠道为 [Coahuilite/ZeroPointLauncher](https://github.com/Coahuilite/ZeroPointLauncher)。这里的“官方”仅指该维护者确认的本 fork 发行，不表示原作者或上游仓库为本 fork 背书；第三方沿用源码、保留署名或遵循开源许可，也不意味着获本 fork 维护者认可。

对第三方修改版建议采用独立的产品与发行者标识，并在下载页及应用关于页明确：

- 这是第三方派生版本，由谁修改、发行和提供支持。
- 基于哪个上游版本、对应源码与适用许可在哪里获取。
- 与本 fork 维护者无官方关联，修改、收费与支持由第三方自行负责。

例如：

> 本版本由 Example Team 独立维护，基于 ZeroPointLauncher 的指定版本修改。发行、修改与支持由 Example Team 负责，未获本 fork 维护者背书。

## 来源署名不是官方背书

可以准确说明“基于 ZeroPointLauncher”并链接来源，也应保留适用的版权和许可声明。不要要求第三方为了改名而删除真实来源或版权署名。

对维护者有权控制的名称、Logo、域名、签名身份或认证标识，建议仅允许不会造成官方关联误认的使用：不把第三方修改版包装成本 fork 官方原版，不伪造官方签名、认可或安全保证，不把第三方收费支持描述为维护者提供的服务。发现许可文本被删改或适用范围被伪装时，应按相关文件真实许可判断，不能用一个错误的许可证标签替代义务。

`ZeroPointLauncher` 是继承的项目名称。目前不宣称本 fork 对该名称拥有已注册商标或排他权；新 Logo 等资产也须按其实际权属处理。这份提案不能代替对具体标识权利和适用地区规则的确认。

## 代码许可与身份规则各管一件事

MPL-2.0 §2.3 不授予贡献者商标等标识权；§3.4 要求保留相关许可声明。对受覆盖文件的源码分发义务由 MPL 决定，独立新增文件可以使用其他许可；不能以“闭源部分存在”为由宣称整个派生产品违反 MPL，也不能以“MPL 兼容”为由声称派生产品是官方发行。[MPL 正文](https://www.mozilla.org/en-US/MPL/2.0/)

Mozilla 也将软件许可和品牌身份区分，并允许准确说明技术来源、禁止暗示官方关联。这是可借鉴的表达方式，不代表本 fork 拥有 Mozilla 的权利或可以直接照搬其商标规则。[Mozilla Trademark Guidelines](https://www.mozilla.org/en-US/foundation/trademarks/policy/)

协作者需要确认哪些发行标识由维护者有权控制，再将这份提案定稿为可执行的品牌政策；当前不宣称已经具备安装包签名或来源验证功能。
