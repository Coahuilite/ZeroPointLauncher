# 分层文件系统：继承可复用，运行修改相互隔离

本文定义 v0.1 的行为提案。`layerfs` 是实例内容解析与物化规划内核，不是文件系统驱动；旧实现的证据见[索引](legacy-evidence.md)。数据布局和 Java 类型在实现切片中确定，以下语义先保持稳定。

## 保留理念，重新定义实现契约

| 原作者的理念 | 新模型中的表达 | 明确变化 |
| --- | --- | --- |
| 子实例覆盖父实例，不改父实例 | 单父继承、固定父修订、可追溯覆盖 | 不再以可变名称作为引用身份 |
| image 可继承，运行目录修改不继承 | 不可变内容层与实例私有工作区分离 | 运行结果必须显式提升为新层才可被继承 |
| 多实例共享内容，存档可共享 | 不可变内容复用与显式共享可写组分开 | 不根据 Java 版本自动加入隐藏分享器 |
| include、exclude、shareDir | 来源选择、来源排除、删除标记、物化策略 | 逻辑粒度不固定为二级目录；目录链接不是覆盖语义 |
| 差异用于升级和迁移 | 带旧基线的三方比较与预览 | 冲突不能靠重新映射覆盖用户修改 |

这些变化适用于新格式。旧规则通过迁移预览逐项解释，不能直接用新默认值重解释旧数据。

## 实例、层与运行数据

- `InstanceId` 是稳定身份，显示名和磁盘位置可以改变。重命名不改变父引用。
- 实例配置形成不可变修订；每个修订最多引用一个确定的父实例修订，并拥有自己的内容层。解析前检查缺失引用和继承环，不人为限制继承深度。
- 父层升级产生新修订，现有子实例不会随之漂移。切换父修订是一次可预览的升级操作。
- 层包含逻辑路径、内容引用和规则；受管理内容一旦发布为修订，不原地修改。复制或链接是宿主的执行选择，不是层身份。
- 私有工作区包含运行时修改和用户数据。它属于一个实例，不属于该实例的可继承内容层。
- 显式共享可写组使用稳定 `SharedGroupId`，与所有实例层分开持久化；加入组是明确选择，不因继承父实例自动加入父实例的可写组。

游戏组件和可移植启动偏好也参与实例修订，继承规则见[实例配置合同](architecture.md)。它们不通过复制某个运行目录中的 `version.json` 隐式获得。

多个实例可以引用同一不可变内容。缓存清理不得删除仍被实例修订、待提交操作或保留恢复点引用的内容；首个切片不要求实现自动垃圾回收。

## 逻辑路径与环境限制

逻辑路径使用相对 `/` 分隔形式，保留大小写。拒绝绝对路径、盘符、空路径段、`.`、`..` 和包含 NUL 的路径；导入器先把已知外部格式转为此形式，不能靠字符串拼接访问磁盘。

逻辑上不同的 `config/A.cfg` 与 `config/a.cfg`，在大小写不敏感宿主上可能冲突。目标宿主的保留名、路径长度、大小写及名称等价限制在物化前校验；不能静默重命名或覆盖。相同逻辑输入在不同宿主上的解析树相同，是否能物化由能力检查报告。

运行目录中现有符号链接、junction 等不能被当成普通目录递归写入。扫描只读，遇到不可读、悬空链接或未知路径报告诊断，不能通过删除修复扫描错误。受管理写入须校验最终目标仍位于授权工作区，显式共享挂载除外；压缩包条目同样遵守此边界。

## 合并顺序与可解释规则

### 顺序固定，来源保留

一个实例的解析输入是固定修订组成的有序组合：

1. 显式配置的不可变共享内容层，按清单顺序由低到高。
2. 从最老祖先到当前实例的内容层。
3. 运行物化时再叠加当前实例私有差异；私有差异不进入可继承解析结果。

每个实例修订记录完整的共享内容引用清单。派生时可以复制该清单为新修订的明确配置，之后不动态追随父实例清单；重复层引用视为配置错误。共享可写挂载不参与上述内容覆盖顺序。

同一路径的普通文件由更高层覆盖。解析器保留各候选来源，而不是只保留最后一个文件，因此可以解释被覆盖项，并在来源排除后重新选取候选。文件/目录类型冲突不能依赖遍历顺序解决。

### 规则在声明层生效

规则的目标范围必须明确为单一路径或整棵子树，不使用“二级目录”推断。每条规则有稳定标识及声明修订。

| 动作 | 行为 |
| --- | --- |
| 普通内容写入 | 为路径增加当前层的内容候选，覆盖更低层同路径候选 |
| 来源排除 | 从已参与组合的指定来源移除匹配候选，其他来源仍可胜出；可指定该来源的全部路径 |
| 来源选择 | 选取已参与组合、未被来源排除的指定来源候选，作为声明层的覆盖项，保留原始来源和选择规则 |
| 删除标记 | 在声明层隐藏该路径或子树的全部低层候选；不删除父层内容 |
| 子树替换 | 明确用一组新条目替换该子树，包含隐藏低层内容；用于目录整体替换或文件/目录类型转换 |

每层先应用来源排除，再应用该层的内容和其余动作。来源选择不能引用后出现的层，也不能选中不存在或已排除的条目。选中内容仍保留原始来源，后代针对该来源的排除同样影响它。

删除标记和来源选择只获得声明层的优先级，后代仍可用明确的新内容覆盖。删除标记与“排除所有来源”在新格式中统一为隐藏低层候选的操作，不能变成阻止所有后代添加内容的全局禁令。

同一层中对同一路径或重叠子树的互相矛盾操作必须报冲突，不采用 JSON 字段顺序决定赢家。一个显式子树替换动作可以携带内部新条目；除此以外，不接受靠重叠删除和新增暗示类型转换。普通目录按文件合并，不因出现一个子目录就隐式替换整棵目录。

同层内部矛盾属于非法声明，不能靠后代隐藏来修复；不同层之间的类型冲突则按全部规则执行后的有效候选判定，后代的来源排除或显式子树替换可以消解它。仍未解决的冲突返回诊断，不提供可用文件树。

### 可判定的例子

```text
基础 A：config/x.cfg = A；mods/old.jar = O
汉化 B：config/x.cfg = B
个人 C：config/x.cfg = C；删除 mods/old.jar
结果：config/x.cfg 来自 C；mods/old.jar 不可见。

C 不写 x.cfg，只排除 B 的 x.cfg：结果回到 A。
C 选择 A 的 x.cfg：结果是 A，解释中显示 C 的来源选择规则。
C 删除 x.cfg，后代 D 添加 x.cfg = D：结果是 D。
```

解析结果包括可见条目、原始来源、胜出动作、被遮蔽来源和冲突。解析不访问磁盘、不下载、不修改目录。输入树的扫描、内容获取和宿主校验通过端口完成。

## 私有写入与显式共享写入

### 默认保护父层和其他实例

游戏可能写入的内容，包括配置和未知用途文件，默认物化为实例私有副本。首次准备建立基线，之后记录或扫描私有新增、修改和删除；再次准备不能把它们当作垃圾清理。

符号链接和硬链接都不是写时复制。只要游戏的普通写入能够改变共享源，就不满足隔离契约。只有宿主能兑现所选不可变共享策略的写入限制时，才允许对已分类的只读制品采用链接优化；否则使用私有复制或真实受支持的写时复制能力。只读失败应可诊断，不偷偷改为共享可写。

存档、截图等用户数据拥有独立保留策略，准备运行树和清理派生文件不删除它们。具体路径分类由 Minecraft/包描述提供默认值，用户显式修改后保留其选择；未知文件默认保留并报告，不视为可丢弃缓存。

用户将私有差异“提升为内容层”时，先选择范围并生成新修订；不能顺便提升存档、日志或账户信息。提升后的内容才参与子实例继承。

### 共享组是有意识的共同写入

用户可以把存档等目录指定为共享可写组。界面必须显示共享身份、参与实例和写入会被共同观察到的含义。挂载点及其子树不再同时接受层内容、私有差异或第二个共享挂载；重叠必须先显式迁移或解决，不能静默遮住已有数据。

共享可写不能在能力不足时偷偷改成独立副本，否则“共享”已经失效。无法挂载时报告原因；复制为独立数据只能作为用户另选的操作。

同一实例以及相同共享组的写入/游戏使用默认互斥，不同实例且不共享可写资源时可以并行。锁按资源身份而不是展示路径识别，避免同一目录别名绕过保护。保护覆盖本启动器管理的会话，不声称能阻止外部程序修改共享目录。

## 升级比较旧基线、新基线和用户现状

对每个受管理路径，设 `A` 为上次应用的完整内容基线，`B` 为目标新内容基线，`U` 为当前工作区的实际结果，缺失也是一种状态。A/B 都包含对应修订的不可变共享层、祖先层、**当前实例自身内容层及规则**解析后的结果，不含私有差异或共享可写数据；无父实例同样有自身的内容基线。

| 条件 | 结果 |
| --- | --- |
| U = A | 用户未改动，应用 B |
| B = A | 上游未改动，保留 U |
| U = B | 双方结果相同，无冲突 |
| 三者其余不同 | 冲突，保留当前有效内容及新候选，等待选择 |

比较包含类型与内容身份，不能只按修改时间判断。首版不自动合并配置文本。用户选“保留个人”“采用新版”或显式自定义结果后，记录对应的新基线与私有差异；未解决冲突的升级不得提交为就绪。

例：旧配置为 A，上游改成 B，用户改成 U，三者不同则冲突；上游删除一个用户已修改的文件也属于冲突。只在上游删除、用户未改动时删除运行副本，父层旧修订仍可保留用于恢复。

升级内容回退不等于回退游戏写过的世界存档。共享可写组和独立用户数据不参与内容层自动回滚；涉及其移动或格式转换必须另行预览和备份。

## 物化、提交和恢复

物化计划包含目标实例/修订、预期工作区代次、来源条目、创建/替换/删除动作、私有保留项、共享挂载、所需能力和占用资源。计划和执行结果分离，缺失制品可以列在计划中，但必须全部获取并验证后才允许报告就绪。

执行先验证预期代次、资源占用和磁盘能力，再暂存和提交；所有写操作有可恢复记录。跨目录更新不假设一次原子重命名就能完成整个事务。具体日志格式由实现确定，必须满足：

- 提交完成前不能把新工作区标记为可启动。
- 失败、断电或取消后，恢复流程能区分旧就绪、新就绪和需要修复的中间态；不能把半棵目录当成成功。
- 不可覆盖的用户修改、未知文件或共享资源冲突报告到路径；先前可用内容和必要恢复输入保留到安全提交。
- 取消在安全点生效；越过提交点可以完成并报告取消未生效，不谎报回滚。删除暂存只针对确认归本操作所有的内容。
- 执行前和提交前核对占用与预期状态；检测到外部改动时重新比较或报冲突，不能使用过期预览直接覆盖。

准备操作将占用交接给已创建的游戏会话，游戏退出且文件收尾完成后才释放。UI 关闭或启动器进程消失不是游戏退出证据。占用记录应支持按进程身份恢复核实；无法确认是否仍被使用时，受影响实例/共享组保持明确的待核实占用，其他独立实例仍可工作。运行会话契约见[运行时](runtime.md)。

## 旧数据导入是受控转换

先扫描旧实例、image、运行目录、分享器和规则，生成预览：来源对应关系、私有差异、共享数据、不能解释的规则、目标位置及空间需求。只读扫描不得调用旧映射器“整理”源目录。

导入写入新工作区，保留旧目录作为恢复来源。旧 `include/exclude/shareDir` 的作用域、二级目录粒度和实际链接目标必须在样本中逐项核对；无法确定的差异交给用户选择，不能把名字相近当成语义相同。新格式不保留扫描错误时删除路径、无条件提权或修改父层等危险行为。

对用户选择保留共享的目录，预览必须列出仍会共同写入的数据；对选择独立副本的目录，明确今后不再共享。未完成必要选择或复制验证时，不将导入实例标记为可启动。

## 文件系统验收场景

| 编号 | 输入/动作 | 必须观察到的结果 |
| --- | --- | --- |
| FS-01 | 多级父修订、改名、缺失引用与继承环 | 正常链确定性解析；改名不破坏引用；缺失/环有明确错误 |
| FS-02 | 共享层、祖先、当前层分别提供同路径文件 | 按规定顺序胜出，解释包含原始来源和遮蔽关系 |
| FS-03 | 来源排除、来源选择、删除及后代重新添加 | 与本文例子一致；缺失选择和同层矛盾报冲突 |
| FS-04 | 深层文件覆盖、文件/目录冲突与显式子树替换 | 支持超过二级路径；类型冲突不靠遍历顺序解决 |
| FS-05 | 同一基线派生两个实例，其中一个修改配置并重新准备 | 父层和另一个实例未改变；修改实例保留其私有结果 |
| FS-06 | 私有新增/删除后创建子实例，再显式提升选定差异 | 提升前不继承；提升后仅选定内容进入新层 |
| FS-07 | 两实例加入同一可写组或存在重叠挂载 | 并发使用受阻或排队；重叠先解决；不支持共享时不冒充复制成功 |
| FS-08 | A/B/U 相等组合、新增、双方修改、修改/删除冲突，以及无父实例的自有内容层升级 | 遵守三方比较表；自有层原内容不误判为私有新增；冲突未解决不提交；存档不随内容回滚 |
| FS-09 | 创建、替换、提交、取消各阶段注入故障并重启 | 能恢复到明确状态；无半成品就绪、父层损坏或用户数据丢失 |
| FS-10 | 改变链接能力、只读能力或权限 | 逻辑树不变；物化策略有据可查；可写内容不会意外共享 |
| FS-11 | 大小写冲突、保留名、穿越条目、外部链接或扫描失败 | 物化前诊断；写入不越界；扫描不删除路径 |
| FS-12 | 含旧规则、私有修改和共享存档的受控旧实例样本 | 可预览差异，写入新工作区，原数据保留；未知规则需解决 |
| FS-13 | 预览后外部修改文件、并发提交或游戏仍占用 | 拒绝过期写入；占用交接及恢复不因窗口关闭而失效 |
| FS-14 | 持久父层更新但子实例仍指向旧修订 | 子实例结果不漂移；只有显式升级改变基线 |

FS-01～FS-04、FS-14 已有纯解析实现与测试；其他场景仍待后续切片。实际证据及纯解析、临时目录恢复和真实宿主行为的验证分工见[验收](acceptance.md)。
