# 分享前检查公开内容

分享本轮文件系统原型时，提交源码、测试、规格和标准 Gradle Wrapper；不提交本机运行记录、账户数据或构建报告。文档使用仓内相对链接，命令以仓库根目录为起点，Java 位置由本机 `JAVA_HOME` 提供。

## 检查实际要提交的内容

在仓库根目录使用 PowerShell 7：

```powershell
pwsh -File tools/check-share.ps1
pwsh -File tools/test-check-share.ps1
git diff --check
git diff --cached --check
git status --short
```

检查器同时读取暂存版本和工作区候选，避免“文件已经改干净，但暂存区仍含旧值”。它检查用户主目录、本机仓库绝对路径、常见令牌/私钥、硬编码秘密和私密文件名；只报告位置及规则，不回显命中值。

已提交的 checkout 可用 `pwsh -File tools/check-share.ps1 -Tracked` 检查。二进制、图片和 Git 历史另行审核；文本规则不能证明不存在所有秘密。本轮新增的二进制应只有标准 `gradle-wrapper.jar`，不能把截图、实例包或日志压缩包顺便加入提交。

- 用 `git diff --cached` 阅读实际提交内容，不只查看当前编辑器缓冲区。
- 不提交 Gradle 本地缓存、测试 HTML/XML 报告、IDE 配置和用户级 Java 配置。报告可能包含运行机器路径。
- 测试数据使用合成实例和逻辑路径；需要测试非法路径时使用虚构值，不复制开发机目录。
- 避免发布完整终端截图、环境变量转储、构建日志或崩溃转储；分享测试结论和可复现命令即可。
- 使用 GitHub 的保护功能前先确认设置，不能把服务器端检查当作本地隐私审查的替代。

## 提交身份与历史也会公开

提交作者姓名、邮箱和提交说明属于公开内容。提交前使用愿意公开的身份；需要隐藏个人邮箱时使用本人 GitHub 提供的 noreply 地址，不伪造他人的身份。

本轮在原有 fork 历史上继续开发，不重写上游历史。旧源码里已有的开发机测试路径不应复制到新实现或运行说明。若发现真正泄露的凭据，应先撤销凭据，再另行处理历史清理；在最新文件里删除值不等于删除历史。

远端推送需取得仓库维护者授权；推送前确认目标是维护者自己的 fork 分支，而不是上游归档仓库。
